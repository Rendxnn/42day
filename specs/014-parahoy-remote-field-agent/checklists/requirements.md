# Checklist de calidad de requisitos

**Propósito**: comprobar que la especificación es completa, verificable y no deja decisiones de producto al
implementador. Esto evalúa el texto, no la implementación.

- [x] CHK001 El objetivo móvil y la dependencia del Mac/Remote están declarados sin prometer ChatGPT Voice.
- [x] CHK002 Los actores, límites de autoridad y separación staging/producción son explícitos.
- [x] CHK003 Cada historia P1 tiene una prueba independiente y escenarios Given/When/Then.
- [x] CHK004 El flujo de investigación define fuentes, ambigüedad, evidencia y prohibición de inventar.
- [x] CHK005 Prepare, confirmación, commit, expiración, revisión e idempotencia están especificados.
- [x] CHK006 Crear/asignar y actualizar perfil tienen contratos separados y semántica de patch clara.
- [x] CHK007 Apariencia, imagen, links, Google Reviews, QR activo y perfil publicado cubren consentimientos.
- [x] CHK008 El ciclo de importación de imagen, SSRF, límites, lease y recuperación está definido.
- [x] CHK009 OAuth define discovery oficial, consentimiento, JWT, client allowlist, DCR y revocación.
- [x] CHK010 El transporte MCP, schemas, errores y tool annotations tienen contratos concretos.
- [x] CHK011 Los límites de rate, logging y datos prohibidos son medibles.
- [x] CHK012 El plugin, task projectless, verificación de ambiente y fallback están definidos.
- [x] CHK013 Compatibilidad con feature 009 y rollback no destructivo están descritos.
- [x] CHK014 Los casos límite de Remote, OAuth, concurrencia, imagen y datos ambiguos están cubiertos.
- [x] CHK015 Los criterios de éxito y gates local/staging/producción son cuantificables y separados.
- [x] CHK016 El fuera de alcance evita decisiones implícitas sobre voz, scraping, cámara, SQL, NFC y producción.
